# برنامج NoonDealsEgy — نسخ عروض نون بروابط Yajny الخاصة بك

## جديد هذه النسخة
- يقرأ بوستات `@Hi_pro1` و`@tawfiry` (أو القنوات المكتوبة في متغير `TELEGRAM_SOURCES`) وينشر في `@NoonDealsEgy`.
- يفك اختصارات `yajny.com/l/` إلى رابط نون النهائي، وينظف معاملات الإحالة المعروفة (`shareId` و`utm_*` و`pcl`) ويحتفظ بمعرّف المنتج والعرض `o`.
- يدخل رابط نون في **حسابك أنت على يجني** عبر متصفح Playwright، ويراقب سجل الروابط ليأخذ الرابط الجديد فقط.
- يستبدل رابط المنافس، ويضع أكوادك `HZ26` إلى `HZ30`، وينسخ الصور/الألبومات.
- يخزن روابطك التي تم إنشاؤها في SQLite؛ لو ظهر نفس رابط المنتج والعرض يستعيد رابطك الموجود.
- **لا ينشر بوستًا لو فشل فك الرابط أو تأكيد إنشاء رابطك**. لا يستبدل رابط المنافس بالافتراضي أبدًا.
- يبدأ من الجديد فقط `BACKFILL_LIMIT=0` عند أول تشغيل، ويحتفظ بسجل النسخ من مجلد `/data`.

## تحذير أساسي
يجني **لا يوفر لنا API عامًا موثقًا**. هذه محاولة أتمتة لصفحة «شارك واربح» التي رأيناها، وقد تتطلب تعديل محددات الحقول إذا غيّر الموقع تصميمه، أو إعادة تسجيل الدخول إذا انتهت الجلسة. **لم نختبر إنشاء رابط حقيقي على حسابك**؛ فلا تعتبري النشر تلقائيًا مضمونًا قبل تجربة فعلية. لا يجوز تجاوز CAPTCHA أو أي حماية يمنعها الموقع.

## تشغيل أولي مرة واحدة على Windows
1. افتحي المجلد في PowerShell.
2. ثبتي المكتبات والمتصفح:
```powershell
py -m pip install -r requirements.txt
py -m playwright install chromium
```
3. أنشئي جلسة يجني **محليًا فقط**:
```powershell
py bootstrap_yajny.py
```
4. هيفتح Chrome/Chromium؛ سجلي الدخول إلى حسابك الخاص على Yajny وادخلي صفحة `https://yajny.com/ar-eg/user/share-and-earn` ثم ارجعي إلى PowerShell واضغطي Enter.
5. الملف السري `yajny_session_PRIVATE.txt` يحتوي على جلسة متصفحك بصيغة Base64 (**ليست تشفيرًا**). **لا ترسليه لأي شخص ولا ترفعيه على GitHub.** انسخي محتواه إلى Railway Variables باسم `YAJNY_STORAGE_STATE_B64`. لو الجلسة انتهت، أعيدي الخطوات.

## النشر على Railway
- **ارفعي محتويات المجلد في Service الخاصة بنون فقط**؛ لا تلمسي Service ترنديول.
- استخدمي Dockerfile الموجود؛ يثبت Chromium ومتطلبات Playwright. لا تضعي Start Command مختلفًا عن `python noon_forwarder.py`.
- أضيفي متغيرات `.env.example` بالقيم الصحيحة. `TELEGRAM_SESSION_STRING` قديمه يظل كما هو. أضيفي الجديد `YAJNY_STORAGE_STATE_B64`.
- أبقي Volume موصولًا بـ `/data`، ولا تحذفي ملف `noon_mirror.sqlite3`؛ فيه النسخ السابقة وخريطة روابطك الجديدة.
- شغلي Replica واحدة فقط. تشغيل البوت أكثر من مرة قد يكرر نشر البوستات.
- متغير `BACKFILL_LIMIT=0` يمنع استيراد تاريخ القنوات للمصدر الجديد. إذا كان عندك `BACKFILL_LIMIT=20` عدليه إلى صفر.

## كيف تتأكدي أنه صحيح؟
- بعد النشر `READY` ثم `BASELINE` للقنوات الجديدة.
- عند ظهور منتج جديد: `Yajny created own link ...` ثم `NEW ...` أو `ALBUM ...`.
- افتحي رابط البوست وانقري على المنتج ثم افتحي حساب يجني: لازم الرابط يظهر عندك في «الروابط السابقة».
- عند الفشل ستجدي `NO PUBLISH ...` أو `PENDING ...`، ولن ينشر رابط المنافس. لو حصل خطأ `Yajny form inputs not identified` فموقع يجني تغير أو الجلسة انتهت.
- **ابدئي بإرسال بوست تجريبي واحد**. لم يُتح إجراء عملية إنشاء حقيقية بدون بيانات الدخول الخاصة بحسابك.

## نقاط يجب معرفتها
- النسخة دي لا تستطيع ضمان إنه كل منشور قابل للنسخ أو إنه رابط يجني يحقق عمولة؛ ده حسب شروط يجني.
- لا تتعامل حاليًا مع روابط أفلييت مخفية داخل النص باستخدام `MessageEntityTextUrl`، لتجنب تسرب رابط المنافس. البوستات دي هتترفض ويظهر سببها في الـLogs.
- أي بوست بدون رابط منتج نون مفهوم لا ينشر؛ ده قرار متعمد للسلامة.
- التعديلات في الصور القديمة ممكن تحتاج إعادة إرسال؛ البرنامج يعدل النصوص فقط عند تغيرها.
- لو الروابط المختصرة تستخدم redirect بجافاسكريبت فقط، البرنامج يفشل بأمان بدل التخمين.

## إصلاح v3: منع خطأ 403 من نون
- كان برنامج v2 يستخدم follow_redirects=True؛ يجني يرجع 302 ثم يحاول البرنامج تنزيل صفحة Noon ويستقبل 403 من حماية الموقع.
- في v3 يقرأ البرنامج Location من رد يجني 302، ويتحقق أن الوجهة نطاق Noon، ثم ينظف معاملات التتبع. **لا يحتاج تنزيل صفحة Noon** ولا يحاول تجاوز الحماية.
- لا يتم إنشاء رابط يجني الخاص بك إلا بعد نجاح استخراج وجهة Noon. إذا لم يستطع قراءة التحويل أو فشل تسجيل دخول يجني فلن ينشر البوست.
- ارفعي هذه النسخة على Service نون فقط، واتركي Railway Variables كما هي (ومنها YAJNY_STORAGE_STATE_B64). احتفظي بقاعدة البيانات/قرص /data لمنع التكرار.
- هذا الإصلاح تم التحقق منه برمجياً ولم يُختبر بعد على حساب يجني أو Railway الفعلي.


## تحديث v4 — إصلاح تحديد حقول صفحة يجني
- كان البرنامج يعتبر خانة رابط المتجر خانة «اسم العرض» أيضًا بسبب كلمة «العرض»، فيوقف النشر. تم فصل التعرف على الحقلين.
- في حالة اختلاف الصفحة/انتهاء تسجيل الدخول، تظهر رسالة `Yajny form check` مع أسماء الحقول فقط (دون بيانات الجلسة).
- راقبي ظهور `Yajny created own link` قبل `NEW` أو `ALBUM`. لا تعيدي تسجيل الدخول أو تغيير المتغيرات إلا لو ظهر تشخيص انتهاء الجلسة.
- احتفظي بقاعدة البيانات في `/data` ولا تستخدمي النسختين v3 و v4 في خدمتين شغالتين معًا.
